\chapter{Methodology}
\label{cha:methodology}

In this chapter, we explain the methodology used in the development of this work. We begin 
by detailing how the data was obtained and the logic behind its selection. Additionally, we 
present the data augmentation techniques applied to the dataset and describe the methodology 
employed in training the models.

\section{Data Collection}

The \gls{dgt} conducted an extensive aerial photogrammetric survey of Continental Portugal, 
resulting in a high-resolution orthophoto dataset covering the years 2018 to 2021. 
These orthophotos provide a valuable resource for geographic and environmental analysis, 
including fire risk assessment.

\subsection{Technical Specifications}
The orthophotos used in this study have the following characteristics:

\begin{itemize}
    \item \textbf{Spatial Resolution:} 25 cm/pixel.
    \item \textbf{Spectral Resolution:} Four-band imagery, including Red, Green, Blue (RGB), 
          and Near Infrared (NIR), enabling vegetation analysis.
    \item \textbf{Geographic Coverage:} Complete coverage of Continental Portugal.
    \item \textbf{Reference System:} 
        \begin{itemize}
            \item \textbf{EPSG:3763} - A projected coordinate system optimized for accurate 
                  distance measurements, ideal for mapping, surveying, and GIS applications in Portugal.
            \item \textbf{EPSG:4258} - A geographic coordinate system primarily used for geodetic 
                  applications and alignment across Europe.
        \end{itemize}
\end{itemize}

The orthophotos are publicly available through a Web Map Tile Service (WMTS), allowing for 
efficient data retrieval and integration into research applications. Our dataset consists of 
RGB and IRG orthophotos extracted from this open data source. To automate image retrieval, 
a Python module was developed to extract images based on bounding box coordinates corresponding 
to the residential locations in the dataset. In total, 1929 RGB and IRG images were acquired.

For fire risk assessment, a 62.5-meter radius was defined to ensure that the analysis 
captures the area surrounding each house within at least 50 meters, with the additional 
12.5 meters accounting for the house itself. This approximation accounts for variability in 
house shape and size. Each extracted image is represented as a 500 x 500 pixel tile.

\section{Data Augmentation}

To enhance the dataset and improve model generalization, various data augmentation 
techniques were applied. These augmentations introduce diversity, helping the model 
learn robust features while mitigating overfitting, a crucial factor given the dataset's relatively 
small size and the complexity of the classification task.

Deep learning models, particularly complex architectures, have a high capacity for 
capturing intricate relationships in data. However, when trained on limited data, 
they are prone to memorizing training images rather than learning meaningful 
patterns. By applying data augmentation, the model encounters different variations 
of the same data, reducing its reliance on exact memorization and improving 
its ability to generalize to unseen samples.

As shown in Table \ref{tab:augmentations}, four augmentation techniques were 
employed \cite{torchvision2016}. Horizontal and vertical flips were applied 
with a probability of 50\%, ensuring that vegetation and terrain appear in 
varied orientations relative to houses. Random rotations within a $[-30^{\circ}, 30^{\circ}]$ 
range further increased variability, allowing the model to recognize patterns from 
different perspectives. Additionally, brightness adjustments within a $[-20\%, 20\%]$ 
range accounted for lighting variations due to different capture times and cloud cover.

both RGB and IRG images, they were applied randomly during training. As a result, no two 
training instances were identical. Additionally, some augmentations, such as 
brightness variation, may behave differently between the two formats due to 
differences in spectral information, further increasing dataset variability.


\section{Environment Setup}

To ensure a stable and reproducible training environment, we used Poetry \cite{poetry2023} for 
dependency management and a Docker \cite{docker2023} container with CUDA support for execution 
on the NOVA DI-Cluster. This setup enables efficient resource allocation while leveraging GPU 
acceleration for faster training.

Training was conducted on the \textit{alakazam} nodes of the cluster, equipped with the 
following hardware specifications:

\begin{itemize}
    \item \textbf{CPU:} Dual AMD EPYC 9124 (64 threads total)
    \item \textbf{GPU:} NVIDIA L4 (23GB VRAM, CUDA 12.0)
    \item \textbf{Memory:} 251GB RAM
\end{itemize}

The Docker container provides several command-line arguments that allow flexible control 
over the training process. The most frequently used parameters include:

\begin{itemize}
    \item \texttt{--train}, \texttt{--test}: Specify whether to train a new model or evaluate an existing one.
    \item \texttt{--algorithm}: Select the model architecture for training or evaluation.
    \item \texttt{--num\_epochs}, \texttt{--batch\_size}: Define the number of training epochs and batch size per iteration.
    \item \texttt{--lr}, \texttt{--wd}: Control the initial learning rate and weight decay for optimization.
    \item \texttt{--load\_weights}: Load pre-trained model weights for fine-tuning.
    \item \texttt{--save\_as}: Specify the output filename for storing the trained model and metrics.
    \item \texttt{--num\_classes}: Define the number of target classes for classification.
    \item \texttt{--ndvi}: Enable the use of a fourth channel for the NDVI index in input images.
\end{itemize}

By defining these parameters at runtime, the training pipeline maintains flexibility while 
ensuring consistency across different experiments. This setup facilitates efficient 
experimentation without requiring modifications to the core training script.


\section{Training, Validation, and Testing}

This section outlines the methodology used for training, validation, and testing of the 
chosen models. The discussion of the results is deferred to a later chapter.

\subsection{Dataset Splitting and Augmentation}

The dataset is initially divided into training and testing sets using a 90\% / 10\% 
split, resulting in approximately 1736 training samples and 193 testing samples. 
To monitor the model's learning progress, the training set is further split into 80\% 
training and 20\% validation, yielding 1388 non-augmented training samples and 
348 validation samples.

To enhance model generalization, data augmentation is applied during training. Horizontal 
and vertical flips introduce four variations per image, while random rotation and 
brightness adjustments create a large number of unique transformations across multiple epochs. 
Although the exact number of augmented samples cannot be directly quantified, this process 
effectively expands the dataset, improving robustness against overfitting.

\subsection{Training Methodology}

The training process follows a transfer learning approach, where pre-trained models 
are fine-tuned for fire risk classification. Models are initialized with ImageNet weights 
and trained using the AdamW optimizer. The loss function used is Binary Cross-Entropy 
with Logits Loss (BCEWithLogitsLoss), which is well-suited for binary classification tasks.

To prevent overfitting, an early stopping mechanism is implemented, stopping training 
if the validation loss does not improve for five consecutive epochs (patience parameter). 
Based on observations of validation loss stabilization, training typically lasts between 15 
and 21 epochs. Additionally, the best-performing model (determined by validation loss) is 
saved to ensure the most effective version is retained.

Training is conducted using a batch size of 16 for ResNet-50 and 8 for EfficientNet-B5 
and DenseNet-161, due to GPU memory constraints. 

To ensure robustness and reliability, all training, validation, and testing runs are repeated 
multiple times allowing for a more accurate assessment of model 
performance and generalization.

\subsection{Model Evaluation}

To assess model performance, we analyze both training progress metrics at the best validation loss epoch and 
final evaluation metrics on independent test data. The key evaluation metrics used include:

\begin{itemize}
    \item \textbf{Validation Accuracy and Loss}: Tracked across epochs to monitor learning stability.
    \item \textbf{Training Accuracy and Loss}: Stored for each epoch to analyze potential overfitting or underfitting.
    \item \textbf{Test Accuracy}: Measures the model's ability to correctly classify unseen samples.
    \item \textbf{Test F1-score}: Provides a balanced evaluation of precision and recall, crucial for imbalanced datasets.
\end{itemize}

To facilitate further analysis, all training metrics (accuracy, loss, and validation performance) 
are recorded and stored in a JSON file at each epoch.

Each model is trained using the three different input types: RGB, IRG, and RGB+NDVI. The performance 
of each configuration is analyzed to determine the most effective feature representation for fire risk 
classification.

\subsection{Training Strategy and Hyperparameter Tuning}

The training process is structured into different stages to optimize model performance:

\begin{itemize}
    \item Learning Rate Tuning: Models are first trained with varying learning rates to determine the optimal initial rate.
    \item Weight Decay Optimization: Once an appropriate learning rate is established, different weight decay values are tested to improve generalization.
    \item Gradual Unfreezing (DenseNet-161): Due to its initial suboptimal performance, a gradual unfreezing strategy was employed for DenseNet-161, as explained in the next section.
\end{itemize}

\subsubsection{Gradual Unfreezing Strategy for DenseNet-161}

Fine-tuning pre-trained models can lead to instability and overfitting, particularly when working 
with smaller datasets. In initial training runs, unfreezing all layers of DenseNet-161 simultaneously 
risked updating deep feature representations too aggressively, potentially leading to feature 
degradation rather than effective adaptation. To mitigate this, we implemented a gradual unfreezing 
strategy, where layers were progressively unfrozen throughout training.

Instead of unfreezing all layers at once, which can lead to excessive parameter updates, layers were 
incrementally unfrozen based on the current epoch. The process follows these steps:

\begin{enumerate}
    \item \textbf{Epoch 0--2}: Only the classifier (fully connected layer) is trainable, while all convolutional layers remain frozen.
    \item \textbf{Epoch 3}: The shallowest layers (initial convolutional blocks) are unfrozen and fine-tuned.
    \item \textbf{Epoch 6}: Mid-level layers are unfrozen, allowing deeper feature representations to be fine-tuned.
    \item \textbf{Epoch 9}: The final layers are unfrozen, enabling full fine-tuning of the network.
\end{enumerate}

This approach is designed to allow the model to first adapt high-level features (classifier), then 
low-level spatial features, followed by mid-level and deep feature representations. By gradually 
unfreezing layers, we aim to retain valuable pre-trained features while progressively adapting the 
model to the fire risk classification task.

The impact of this strategy is further analyzed in the results section, where we evaluate its effect 
on model performance.


\subsection{Ensemble Merging Strategy and Evaluation}

To aggregate predictions from the individual models, a majority voting strategy was
employed. Each network independently produced a classification output, and the final
decision was determined based on the most frequently predicted class. This method
ensures that no single model dominates the final prediction and leverages the collective
decision-making power of multiple architectures.

Majority voting was chosen over probability-based soft voting because it reduces the
influence of individual model biases and works well when all models perform at a similar
level. Additionally, given the binary nature of the fire risk classification task, majority
voting provided clear and stable results. 

By implementing these ensemble strategies, the goal was to assess whether incorporating 
additional spectral information improves classification performance and to determine
how well fire risk can be predicted using only RGB imagery. This comparison is particularly 
important for real-world applications, where access to multi-spectral data may be
limited.

\subsubsection{Ensemble Performance Metrics}

The ensemble models are evaluated using the following key metrics:

\begin{itemize}
    \item \textbf{Final Accuracy}: Measures the overall classification performance of the ensemble.
    \item \textbf{F1-score}: Ensures a balanced evaluation of precision and recall, accounting for class imbalances.
    \item \textbf{Confusion Matrix}: Provides insights into misclassification trends by comparing errors between independent models and the ensemble.
\end{itemize}

By combining the strengths of multiple models, the ensemble approach aims to improve classification 
consistency and mitigate individual model biases. 

\subsubsection{Analysis of High-Confidence Misclassifications}

To further evaluate the ensemble's reliability, we analyze cases where all models unanimously 
predict the same class, yet the ground truth label differs. These high-confidence misclassifications 
are particularly relevant, as they may reveal potential issues with the dataset, such as 
labeling inconsistencies or ambiguous features that make classification challenging. 

By investigating these cases, we aim to identify whether the errors stem from systematic model 
biases, limitations in the available features, or inaccuracies in the ground truth labels. 
Understanding these misclassifications helps refine both the dataset and the models, ensuring 
a more reliable and interpretable fire risk classification system.
